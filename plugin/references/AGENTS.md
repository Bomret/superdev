# references/

## Purpose

Backend seed templates and runtime references live here. **Backend seed templates** are what `/superdev:setup` turns into a
consumer repo's `docs/agents/*.md`. **Runtime references** are the shared contracts the skills and
subagents read while a scope runs. This doc routes both. It states no contract of its own: each
reference's own opening states its full contract.

## Ownership

This doc owns the routing table below — which reference owns which contract, and which runtime surface
reads it. It owns nothing else. The root [`AGENTS.md`](../../AGENTS.md) owns the working rules that
govern the prose in this folder, chiefly **Backends are pluggable** and the **prompt-architecture
rules**.

## Local Contracts

A reference is canonical for what it owns. A skill or agent that needs the contract reads the file
rather than restating it; a restatement is the one-sided-pin shape the root doc's prompt-architecture
rules name.

Every other file here is a backend seed: a slice store, a code host, or a knowledge base — `deployment.md`
above is a seed of its own kind, one shape for every repository rather than a per-backend choice.
`/superdev:setup` reads each seed twice: to write a document on a first run or a backend switch, and to
compare a configured document with it, listing and offering its seed gaps (ADR 0107).
A slice-store seed's `## Triage record` **List the records**, **Comment on it**, and **Close it** calls, its **Read an anchor's Absorbs line** read, and a code-host seed's `## Edit the pull request body`
section become the configured document's calls that `scope-findings.md`'s `## Deferred findings` resolve
procedure runs (ADR 0121).
The knowledge-base seeds are `knowledge-base-confluence.md`, `knowledge-base-forgejo.md` (a Forgejo or
Gitea repository wiki, reached through `tea` only, with body-link hierarchy and the empty-wiki rule in its
`find`), `knowledge-base-github-wiki.md` (a GitHub repository wiki, reached through `git` and `gh`, with
body-link hierarchy and `<host>` and `<owner>/<repo>` placeholders), and `knowledge-base-local.md`. `/superdev:setup` question D writes `docs/agents/knowledge-base.md`
from the chosen one, and its seed-gap pass compares a configured document with it. `/superdev:publish-kb`
runs the configured templates, and `tests/publish-kb-templates.test.js` runs the Confluence and Forgejo
seeds' templates. The `forgejo-tea-only` drift check reads the Forgejo seed, and the `github-wiki-gh-only` drift check reads the GitHub wiki seed.
Adding a slice-store, code-host, or knowledge-base seed is the **Backends are pluggable** rule in the root
doc.

## Work Guidance

Adding a reference means adding its row above. Changing what a reference owns means changing that row
in the same commit. A row whose `Read at runtime by` column no longer matches the live prose is a
finding for review: no check compares the two.

## Verification

`node scripts/run-tests.js` from the repo root. `scripts/drift-check.js` asserts that every `references/*.md` path a
skill, agent, or reference names exists, that every canonical reference still carries the sections its
readers are sent to, and that a document a check reads is not missing.
